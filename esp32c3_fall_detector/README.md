# Korgan / Қорған — ESP32-C3 Fall Detector & SOS (v3)

Прошивка носимого детектора падений и кнопки SOS на **ESP32-C3** с датчиком
**MPU-6050**. Тревога передаётся по **BLE** в Android-приложение Korgan,
которое отправляет SMS всем получателям и при необходимости звонит первому из них.

Версия прошивки: **3.0.1**, протокол не менялся с 3.0.0.

Как работает алгоритм и какие формулы используются — в [ALGORITHM.md](ALGORITHM.md).

---

## Подключение

| Компонент | Пин ESP32-C3 | Примечание |
| :--- | :---: | :--- |
| Кнопка SOS | `GPIO 0` | Второй контакт на `GND`, внутренняя подтяжка `INPUT_PULLUP` |
| MPU-6050 SDA | `GPIO 4` | I2C, 400 кГц |
| MPU-6050 SCL | `GPIO 3` | I2C, 400 кГц |
| MPU-6050 VCC/GND | `3.3V` / `GND` | Питание датчика |
| Встроенный LED | `GPIO 8` | Синий на SuperMini, активный LOW |
| Внешний LED *(опция)* | `GPIO 1` | Через резистор 220–470 Ом |
| Зуммер *(опция)* | `GPIO 2` | ШИМ 1 кГц |
| АКБ через делитель *(опция)* | `GPIO 5` | Включается `ENABLE_BATTERY_ADC 1`, делитель 2:1 (см. ограничение в [ALGORITHM.md](ALGORITHM.md#6-батарея-по-умолчанию-выключено)) |

`GPIO 2` — strapping-пин. Если зуммер мешает загрузке, отключите его или
перенесите на свободный GPIO и измените `BUZZER_PIN`.

## Что изменилось в v3

- **Нет Wi-Fi.** Модуль не инициализируется: меньше потребление и размер прошивки.
- **Очередь тревог в NVS.** Событие сохраняется до подтверждения телефоном и
  переживает перезагрузку/разряд. При следующем подключении оно отправится снова.
- **Номера событий и ACK.** Формат `FALL:<seq>:<battery>:<uptime>` /
  `SOS:<seq>:<battery>:<uptime>`. Приложение отвечает `ACK:<seq>`, только после
  этого событие удаляется из NVS.
- **Повторная отправка.** Пока событие не подтверждено, оно отправляется каждые
  5 секунд при активном подключении. Приложение дедуплицирует события по `seq`.
- **Разделение FALL и SOS.** Нажатие кнопки приходит как `SOS`, падение — как
  `FALL`; в приложении разные заголовки и текст SMS.
- **Устойчивый BLE.** Поддержка Bluedroid и NimBLE ESP32 core 3.x; корректный
  перезапуск рекламы после отключения телефона.
- **Датчик.** Сброс MPU-6050 при старте, проверка `WHO_AM_I`, повторные чтения
  I2C, автоматическая переинициализация при сбое.
- **Кнопка SOS работает даже при отказе датчика.**

## Протокол BLE

- Имя устройства: `Korgan-C3`
- Service UUID: `4fafc201-1fb5-459e-8fcc-c5c9c331914b`
- Characteristic UUID: `beb5483e-36e1-4688-b7f5-ea07361b26a8`
- Свойства: `READ | WRITE | WRITE_NO_RESPONSE | NOTIFY`
- Кодировка: UTF-8, без завершающего перевода строки

### От устройства к телефону

| Пакет | Значение |
| :--- | :--- |
| `READY:3.0.0` | Устройство готово, можно сбрасывать ошибку датчика |
| `INFO:FW=3.0.0;SENSOR=OK;QUEUE=0;BAT=-1` | Диагностика |
| `ERROR:SENSOR` | MPU-6050 не отвечает, детекция падений недоступна |
| `FALL:<seq>:<battery>:<uptime>` | Подтверждённое падение |
| `SOS:<seq>:<battery>:<uptime>` | Нажата кнопка SOS |
| `PONG` | Ответ на `PING` |
| `ERROR:CMD` | Неизвестная команда |

`battery` — процент `0..100` или `-1`, если ADC не включён. `uptime` — секунды с
момента запуска.

### От телефона к устройству

| Команда | Действие |
| :--- | :--- |
| `ACK:<seq>` | Удалить событие из очереди NVS |
| `PING` | Проверка связи, ответ `PONG` |
| `STATUS` | Отправить `INFO:...` |
| `TEST` | Создать настоящее тестовое событие `FALL` (диагностика) |

## Алгоритм детекции падения

1. **Свободное падение** — `|A| < 0.55 g` не менее 65 мс (отсекает шаги).
2. **Удар** — `|A| > 2.8 g` (или прямой удар `> 4.8 g` без фазы невесомости).
3. **Вращение** — суммарная угловая скорость `> 130 °/с` во время падения.
4. **Покой** — 400 мс на затухание отскока и 1.5 с почти полной неподвижности.
   Если человек встал и двигается, тревога отменяется.

Гироскоп переводится в standby после 3 секунд покоя и мгновенно будится при
движении, что экономит энергию без потери критических фаз падения.

## Сборка

### Arduino IDE

1. Установите ядро **esp32 by Espressif** (проверено на 3.3.11).
2. Откройте папку `esp32c3_fall_detector` (файл `esp32c3_fall_detector.ino`).
3. Плата: **ESP32C3 Dev Module**.
4. Включите **USB CDC On Boot: Enabled**.
5. Прошейте.

### Arduino CLI

```bash
arduino-cli compile --fqbn esp32:esp32:esp32c3 .
arduino-cli upload  --fqbn esp32:esp32:esp32c3 -p COM4 .
```

### PlatformIO

```bash
pio run
pio run --target upload
```

Порт в `platformio.ini` не задан намеренно — PlatformIO определит его сам.
Если нужно, укажите `upload_port`/`monitor_port` локально.

## Ограничения безопасности

В этой сборке **нет bonding и шифрования BLE**. Любое устройство в радиусе
действия может подключиться к характеристике и отправить `ACK`/`PING`/`TEST`.
Для домашнего использования это приемлемо, но не является защитой от
целенаправленной атаки.

Для защищённого варианта нужно:

- включить bonding/LE Secure Connections и фильтровать незабонденных клиентов;
- хранить ключи в NVS;
- добавить проверку подписи команд (HMAC) на уровне протокола;
- учесть, что после включения bonding требуется повторное сопряжение в приложении.

Прошивка не заменяет медицинское оборудование и не гарантирует обнаружение
100 % падений. Это вспомогательное средство для близких.
